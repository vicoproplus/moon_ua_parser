## 1. 基线结论

基线值口径：**单次运行报告值 = 该次运行 7 个计时轮 ops_per_sec 的中位数**；
**发布基线 = 3 次运行的各次中位数的 中位数**（3 个数为奇数个实测轮中位，
基线必为其中一次运行的真实报告值，非插值、非平均）。

| backend | 基线 ops_per_sec | 基线 ns_per_parse | 三次运行中位 ops_per_sec | 最大跨次偏差 |
|---------|------------------|-------------------|--------------------------|--------------|
| native  | 23.64            | 42299995.40       | 21.43 / 24.13 / 23.64    | 11.85%       |
| js      | 66.56            | 15023080.99       | 65.93 / 66.56 / 66.95    | 1.54%        |
| wasm    | 23.95            | 41739215.19       | 24.30 / 23.95 / 22.47    | 7.83%        |

- `ns_per_parse = 1e9 / ops_per_sec`，同一计时源导出的双口径（spec §3 统计口径行）。
- 跨次偏差定义：`|a-b| / ((a+b)/2) × 100`；「最大跨次偏差」取三组两两偏差的最大值。
- 与 T-03 参考值同量级核验：native 23.64 vs T-03 25.77/24.59；js 66.56 vs 65.92/65.83；
  wasm 23.95 vs 23.29——全部远小于 2× 阈值，无异常偏离。

## 3. 测量口径声明

- 命令（cwd = `moon_ua_parser_lib/`）：`moon run --target <native|js|wasm> --release tests/bench`（默认无参模式）。
- 语料全量加载（corpus_size=10000），但**每轮计时只解析声明的分层 stride 子样本**：
  `BENCH_STRIDE=20` → 每轮 `sample_count=500` 条（索引 i×20，按 strata 分组数组
  比例覆盖全部 7 个分层，strata=7）。
- 轮结构：2 个不计时的 warmup 轮 + 7 个计时轮；`ops_per_sec[轮] = 500 / 轮耗时秒`；
  计时唯一经过 seam `clock_pair_diff_us`（moonbitlang/core/bench 单调时钟对，
  统计代码零后端分支）。
- 每轮解析结果折叠进确定性校验和并跨轮比对（`rounds_consistent=true`，9 次全真）。
- 单次运行报告值 = 7 轮 ops_per_sec 的中位数（7 为奇数，中位为实测轮）；
  发布基线 = 3 次运行中位数的中位数。
- 单次运行墙钟：native 211s/188s/192s；js 68s/68s/67s；wasm 185s/191s/195s——全部满足
  「< 6 分钟/次」可行性门。

## 7. 复跑方式

```bash
cd moon_ua_parser_lib
moon run --target native --release tests/bench   # ≈3 分钟
moon run --target js --release tests/bench       # ≈70 秒
moon run --target wasm --release tests/bench     # ≈3 分钟
```

每次运行输出 `bench-config` 前导行、7 行 `bench-round`、1 行 `bench-result`
（backend / ops_per_sec / ns_per_parse / sample_set_hash / samples_checksum /
rounds_consistent）。可选 `-- --smoke` 走 200 条/轮的冒烟模式（阈值占位，
T-06 校准）。
