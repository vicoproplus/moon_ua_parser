## 一、问题陈述

申报书（moon_ua_parser_申报书.md「预期使用场景」节）的第一使用场景是 Web 框架中间件，并点名 Crescent、mars（Hono 风格）、pony（Chi 风格）、mbit（Gin 风格）、Halo（Koa 洋葱）、moonapi（FastAPI 风格）等 10 余个 mooncakes Web 框架是本库的公共下游。但 v0.1 的实际交付是：

1. **零真实集成**：T-10 交付的是 `examples/middleware` 风格示例（git log: "T-10: middleware-style example"），演示自建中间件形态，未对接上述任何一个真实框架。
2. **接入成本转嫁用户**：框架用户要用 UA 解析，必须自行阅读本库 API 并编写框架专属适配层——这正是申报书要消除的成本。
3. **产品化价值主张悬空**：v0.2 定位产品化优先（用户已确认），「被真实框架用户用上」是本库的核心价值；无真实集成则 mooncakes 生态位无法兑现。

受影响用户：框架应用开发者（想一行中间件拿到 browser/os/device）、框架作者（想推荐或内置集成）。

### 5.2 非功能需求（NFR）

| 类型 | 需求描述 | 衡量标准 |
|------|----------|----------|
| 性能 | 中间件自身开销（除解析外）可忽略 | 除解析调用外的中间件逻辑不计入热路径耗时声明，集成测试通过即可 |
| 兼容性 | 锁定目标框架版本区间；区间内 API 变更不破坏中间件 | CI 对锁定区间跑集成测试 |
| 安全性 | 解析失败不中断请求链路（降级为空结果继续处理） | 构造畸形 UA 的集成测试：请求不 5xx，上下文含空结果 |
| 可用性 | 中间件注册 API 与框架惯例一致（各框架命名/注册形态） | 框架官方文档风格对照记录 |
| 失败可诊断性 | 中间件解析异常路径必须可观察：降级事件写入框架日志通道（框架提供的日志口），包含 UA 串摘要与失败原因 | 构造畸形 UA 集成测试，可在框架日志中检索到该摘要与原因 |

### 10.1 术语表

| 术语 | 定义 |
|------|------|
| 中间件（middleware） | 框架请求处理管线中的横切处理单元，本单元指请求入口处解析 UA 并挂载结果的包 |
| 请求上下文 | 框架为单次请求维护的状态对象，中间件向其写入解析结果 |
| 降级 | 解析失败时以空结果继续请求处理，不中断链路 |
| 选型证据报告 | 以来源指针支撑的候选框架对比与裁决文档 |
