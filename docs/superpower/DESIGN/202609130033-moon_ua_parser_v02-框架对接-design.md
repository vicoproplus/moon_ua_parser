## 1. 用户当前理解（认知校准）

申报书的第一使用场景（Web 框架中间件）在 v0.1 只有风格示例（T-10，examples/middleware），未对接任何真实框架。用户已确认：v0.2 产品化优先，对接 1-2 个框架，**具体选谁由设计阶段证据裁决**（AskUserQuestion 已确认该路径）——因此本设计的核心是把「选型」从主观偏好变为可复核的证据裁决程序，并把集成模式收敛为可复制的范本。

## 2. 目标（引用 PRD C2）

G-01 选型证据裁决 / G-02 生产级中间件包 / G-03 mooncakes 发版 + 文档齐备。

## 3. 关键约束（技术）

- 只消费库公开 API（PRD 10.6 S1：`parse` / `parse_browser` / `parse_os` / `parse_device`，src/ua_parser/pkg.generated.mbti:5-11），不改库公开面。
- CI 归属（S3）：集成测试 job 增量合入 .github/workflows/ci.yml。
- 中间件包依赖库版本 ≥0.2.0（S2）。
- 降级语义（PRD NFR 安全性/失败可诊断性）：解析失败不中断请求链路，且异常必须落到框架日志通道可检索。

## 4. 非目标（引用 PRD C3）

不改框架核心、不解析其他请求头、一次不超 2 个框架、不做框架无关抽象层。

## 6. 验收场景（回链 PRD US-XX）

- US-01/FR-02/FR-03：示例应用注册中间件后，请求上下文可取到 browser/os/device 三组结果。
- US-01/NFR 安全性：畸形 UA 请求不 5xx，上下文为空结果。
- US-02/FR-04：README 命令一条跑通示例。
- US-03/FR-01：选型证据报告含对比表 + 裁决 + 来源指针。

## 8. 平台接缝登记（按框架分叉的能力）

| 编号 | 分叉能力 | 接缝层位置 | 共享侧约束 |
|------|----------|------------|------------|
| PS-1 | 框架注册签名 / 请求上下文挂载 API | 各框架中间件包（薄适配层） | 组装与降级逻辑零内联框架条件分支，全部收在共享 helper |
