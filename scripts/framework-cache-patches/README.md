# Framework cache patches (`.mooncakes/` build adapters)

These patch files adapt **registry-cached framework sources** (the gitignored
`.mooncakes/` directory that `moon` populates from the mooncakes registry) so
that the two adjudicated framework pins can coexist in one shared moon
workspace. They are applied automatically by the
"Apply framework cache patches" step in `.github/workflows/ci.yml` (after the
dependency fetch, before the first workspace-level build/test step).

| Patch file | Target (pinned version) | Files touched |
|---|---|---|
| `crescent-async-compat.patch` | `bobzhang/crescent@0.11.1` | `serve_async.mbt`, `serve_request_body.mbt`, `serve_response.mbt`, `websocket/lifecycle.mbt` |

## Why (one line per patch)

- **crescent-async-compat.patch** — the shared workspace MVS-unifies
  `moonbitlang/async` to 0.21.3 (the pin of `mizchi/mars@0.3.12`), which
  changed `http.Request.headers` from `Map[String, String]` to
  `Map[CaseInsensitiveString, String]`; the patch re-types crescent 0.11.1's
  request-header handling at the boundaries (behavior-preserving: CI-keyed
  maps look up case-insensitively natively, String-keyed helpers lowercase
  explicitly). Full mechanism/evidence: T-05 task report §5
  (`.superpowers/sdd/2026-09-13-moon_ua_parser_v02-框架对接/task-5-report.md`),
  runtime evidence `docs/evidence/mw2-example-2026-09-13.log`.

No published version combination of `bobzhang/crescent` × `mizchi/mars` (and
their transitive `moonbitlang/async` / `mizchi/x` pins) compiles unmodified in
a shared workspace — verified against the registry version matrix in T-05.
`bobzhang/crescent` 0.11.1 is the latest release (checked 2026-09-13), so
there is no upgrade path yet.

## mizchi/x Windows fd gating — deliberately NOT shipped as a patch file

The local cache also carries a Windows-only, behavior-preserving patch to
`mizchi/x@0.6.1` (`src/socket/socket_native.mbt`, `src/socket/socket_fd_native.mbt`):
the Int-returning `fd()` accessors are gated with `#cfg(not(platform="windows"))`
because `moonbitlang/async` 0.21.3 made `fd()` return the opaque `@fd_util.Fd`
on Windows (on unix `Fd = Int`, so the published pair compiles unmodified).
On Linux — the CI platform — the gating is a **no-op** (the gated code
compiles identically to pristine), so per the T-06 brief it is not shipped as
a patch file. It remains documented in the T-05 report §5.1 and is marked
in place with `LOCAL CACHE PATCH` comments; anyone building the workspace on
Windows-native after a fresh `moon fetch` must re-apply it (or build on
non-Windows).

## How to apply (mechanism)

From the repository root, after the workspace dependency fetch (the first
workspace-level `moon` command — or `moon install` explicitly — populates the
root `.mooncakes/`):

```
git apply --check scripts/framework-cache-patches/*.patch
git apply scripts/framework-cache-patches/*.patch
```

Verification history (2026-09-13, T-06): the patch was generated by diffing
the pristine registry tarball (`~/.moon/registry/cache/bobzhang/crescent/0.11.1.zip`)
against the adapted cache; `git apply --check` + `git apply` were verified
against (a) a pristine extraction of that tarball and (b) a fresh
`moon install` fetch in a scratch workspace — in both cases the patched
result is byte-identical to the adapted cache that the green T-04/T-05
integration runs used.

Note: empty context lines inside hunks are stored without the conventional
leading single space (authoring-tool whitespace stripping); `git apply` (and
GNU patch) treat such lines as plain context — verified end-to-end above.

- Upstream candidates worth filing once tracked: crescent issue/PR for
